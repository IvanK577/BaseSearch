# Base Search 2.2.0

[English](README.md) | **Українська**

[![CI](https://github.com/IvanK577/BaseSearch/actions/workflows/ci.yml/badge.svg)](https://github.com/IvanK577/BaseSearch/actions/workflows/ci.yml)

Base Search перетворює папки з електронними таблицями на єдину швидку локальну
робочу область із пошуком. Програма імпортує таблиці, зберігає початкові
стовпці, шукає за всіма значеннями, будує аналітику та експортує відфільтровані
результати. Дані залишаються на комп'ютері, де запущено Base Search, якщо ви
самі їх не передасте іншим.

Версія для Windows уже готова до запуску. Для звичайного використання **не
потрібні** Rust, Node.js, npm, інсталятор або окремий GitHub Release.

## Windows: завантаження та запуск

1. На сторінці [репозиторію Base Search](https://github.com/IvanK577/BaseSearch)
   натисніть **Code**, потім **Download ZIP**.
2. Повністю розпакуйте ZIP. Не запускайте програму безпосередньо з WinRAR,
   7-Zip або вікна перегляду архіву Windows.
3. У розпакованій папці відкрийте
   `BaseSearch-master\dist\BaseSearch`.
4. Двічі клацніть **Open Base Search.cmd**. Також можна запустити
   `BaseSearch.exe` безпосередньо.
5. Залиште вибраною **Особисту робочу область** і натисніть **Запустити робочу
   область**. Не закривайте вікно запуску під час роботи.
6. Дочекайтеся стану **Готово**. Робоча область відкриється у типовому браузері.
   Якщо цього не сталося, натисніть **Відкрити робочу область** у вікні запуску.

Це вся звичайна інсталяція: завантажити, розпакувати й відкрити. Програма
портативна, не реєструє інсталятор і не створює службу Windows.

Вбудований Windows-файл наразі не має цифрового підпису. Через це Windows може
показати попередження SmartScreen. Переконайтеся, що ZIP завантажено саме з
цього репозиторію; якщо ви довіряєте завантаженню, виберіть **More info**, потім
**Run anyway**. Manifest пакета містить SHA-256 кожного файла, що постачається.

Не переносіть лише `.exe` окремо від пакета. Усі шість файлів мають залишатися
разом. Запускайте лише одне вікно Base Search: другий процес не зможе використати
той самий локальний порт.

## Перший імпорт і пошук

1. Запустіть **Особисту робочу область**. У цьому режимі не потрібні обліковий
   запис або пароль, а підключення приймаються лише з цього комп'ютера.
2. У браузері відкрийте **Дані**, потім **Імпорт**.
3. Виберіть один або кілька підтримуваних табличних файлів. Перегляньте знайдені
   аркуші, стовпці та попередній перегляд, якщо він доступний.
4. Поставте імпорт у чергу. На сторінці **Завдання** видно перебіг роботи або
   точний текст помилки.
5. Відкрийте **Пошук**, введіть слово, код, компанію, ідентифікатор чи інше
   значення та натисніть **Пошук**.
6. За потреби додайте фільтри. Відкрийте результат, щоб побачити всі імпортовані
   поля початкового файла.
7. Використовуйте **Аналітику** для підсумків, рейтингів, динаміки, зведених
   таблиць, порівнянь і перевірок цін, які підтримують імпортовані стовпці.
8. Відкрийте **Дані**, потім **Експорт**, щоб створити CSV або XLSX для поточного
   запиту.

Base Search підтримує такі вхідні формати:

- Excel: `.xlsx`, `.xlsb`, `.xls` і `.xlsm`
- OpenDocument: `.ods`
- текст із роздільниками: `.csv` і `.tsv`

Фіксований шаблон митних, торговельних, складських чи інших даних не потрібен.
Таблиця з одним стовпцем також є коректною. Книги з макросами читаються як
таблиці; Base Search не виконує макроси.

Якщо мова операційної системи підтримується, інтерфейс одразу використовує її.
У меню **Налаштування > Мова** можна вибрати англійську, українську, німецьку,
іспанську, французьку, польську, португальську, румунську, угорську,
болгарську або китайську.

## Що містить ZIP із GitHub

Готова до запуску папка Windows містить рівно такі публічні файли:

| Файл | Призначення |
| --- | --- |
| `Open Base Search.cmd` | Рекомендований запуск подвійним клацанням |
| `BaseSearch.exe` | Нативне вікно запуску, локальний сервер і вбудований браузерний інтерфейс |
| `base-search-cli.exe` | Необов'язкові команди діагностики, імпорту, пошуку, експорту й обслуговування |
| `README.txt` | Офлайн-інструкція пакета |
| `release-manifest.json` | Версія, ревізія джерел, набір функцій, стан підпису й SHA-256 файлів |
| `LICENSE` | Ліцензія MIT |

Бази даних або дані користувача не додаються. Base Search створює папку даних
під час першого запуску.

Репозиторій також містить джерельний код, потрібний для перевірки та повторної
збірки тієї самої програми:

- `src/`: програма Rust, сервер, імпорт, пошук, аналітика та CLI
- `web-ui/`: браузерна робоча область React
- `scripts/`: відтворюване пакування й перевірка пакета
- `tests/`: інтеграційні тести Rust
- `.github/workflows/ci.yml`: автоматична збірка, тести, пакування і smoke-тести

Локальні кеші збірки, старі версії пакетів, тестові бази, чернетки аудитів,
приватні набори даних, експорти, журнали, `node_modules`, `target` і
`release_packages` навмисно не потрапляють на GitHub. Вони не потрібні для
запуску готової програми й можуть містити локальні або приватні дані.

## Пошук, аналітика та експорт

- SQLite є основним сховищем, а FTS5 виконує повнотекстовий пошук за
  проіндексованими значеннями джерел.
- Розширені правила підтримують вкладені групи «усі/будь-яке», виключення,
  діапазони, порожні значення й умови для конкретних початкових стовпців.
- Результати поділено на сторінки, тому браузер не намагається відобразити всю
  велику базу одночасно.
- Повторно імпортовані однакові рядки пропускаються.
- Аналітика використовує той самий запит і фільтри, що й пошук.
- За наявності відповідних зіставлених стовпців доступні оглядові показники,
  місячна динаміка, компанії, товари, країни, ціни, зведені таблиці, порівняння,
  звіти та профілі компаній.
- Несумісні валюти підсумовуються окремо. Base Search не видає суму в кількох
  валютах за одну суму в доларах.
- Для дуже великих експортів рекомендовано CSV. XLSX має обмеження аркуша Excel.

У виробничому пакеті використано SQLite + FTS5. Експериментальна проєкція
DuckDB OLAP є в джерельному коді за функцією `duckdb-olap`, але не входить до
готової Windows-програми.

## Де зберігаються дані

Типова база нової особистої робочої області розташована тут:

| Платформа | Типове розташування |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Base Search\data\base_search.db` |
| macOS | `~/Library/Application Support/Base Search/base_search.db` |
| Linux | `$XDG_DATA_HOME/base-search/base_search.db` або `~/.local/share/base-search/base_search.db` |

Вікно запуску завжди показує точний шлях до бази. Якщо біля програми вже є
коректний файл `data/base_search.db`, Base Search може повторно використати цю
портативну базу для сумісності. Завантажений пакет не містить папки `data` або
готової бази.

Під час роботи також можуть з'являтися:

- `base_search.db-wal` і `base_search.db-shm`: звичайні робочі файли SQLite
- `base_search.auth.db`: облікові записи та сеанси режиму довіреної мережі
- `uploads/` і `exports/`: вхідні та вихідні файли фонових завдань
- `base_search.db.pre-upgrade-...bak`: перевірена копія перед оновленням

Для ручної резервної копії зупиніть Base Search і скопіюйте всю папку, де
міститься база. Не копіюйте активну базу, поки вікно запуску ще працює.

Перед зміною структури Base Search перевіряє вільне місце, створює та перевіряє
резервну копію, виконує міграцію, перевіряє оновлену базу й залишає копію.
Зберігайте попередню програму та дані, доки не переконаєтеся, що оновлена робоча
область відкривається і пошук працює правильно.

## Особистий режим і довірена мережа

**Особиста робоча область** — рекомендований режим. Вона слухає лише
`127.0.0.1`, не потребує облікового запису й доступна тільки на цьому
комп'ютері. Браузер є інтерфейсом локального процесу; це не означає, що база
розміщена в інтернеті.

**Робоча область у довіреній мережі** — необов'язковий режим для кількох людей
в одній приватній локальній мережі або довіреній VPN. Мережеві користувачі
мають увійти. Доступні ролі: `owner`, `admin`, `editor` і `viewer`.

У мережевому режимі використовується звичайний **незашифрований HTTP**. Ніколи
не перенаправляйте порт Base Search у публічний інтернет і не відкривайте його
для недовіреної мережі. Для доступу через інтернет потрібна окремо налаштована
довірена VPN або TLS reverse proxy; Base Search не налаштовує цей захист.

## Усунення проблем

### Windows не знаходить `BaseSearch.exe`

Найімовірніше, відкрито корінь репозиторію замість готової папки або ZIP
розпаковано не повністю. Відкрийте:

```text
BaseSearch-master\dist\BaseSearch\
```

У папці мають бути всі шість файлів із таблиці вище. Якщо папки `dist` немає,
завантажте ZIP гілки `master` ще раз після цієї зміни та повністю розпакуйте
його.

### Браузер не може підключитися

- Не закривайте вікно запуску й дочекайтеся стану **Готово**.
- Натисніть **Відкрити робочу область** і використовуйте точну локальну адресу,
  яку показано у вікні.
- Якщо порт зайнятий, закрийте інше вікно Base Search або виберіть інший порт і
  перезапустіть.
- Не використовуйте стару закладку після зміни порту.

### Імпорт не завершився

- Відкрийте **Завдання** та прочитайте повний текст помилки.
- Переконайтеся, що розширення підтримується, а файл нормально відкривається в
  програмі для електронних таблиць.
- Перевірте вільне місце для бази, робочих файлів SQLite і завантаженої копії.
- Повторюйте імпорт лише після завершення попереднього завдання.

### Пошук або аналітика неповні

- Очистьте і текстовий запит, і видимі фільтри.
- Відкрийте **Дані > Стовпці** та перевірте початкове поле і його значення.
- За потреби зіставте дату, компанію, товар, країну, вартість, валюту, вагу й
  одиницю вимірювання.
- Звичайні стовпці залишаються доступними для пошуку та експорту без
  спеціального значення.

### Після оновлення відкрилася порожня робоча область

Перевірте шлях до бази у вікні запуску та не видаляйте стару папку. Досвідчений
користувач може явно запустити потрібну базу:

```text
BaseSearch.exe --browser --db "D:\path\to\base_search.db"
```

## Командний рядок

Вбудований `base-search-cli.exe` використовувати необов'язково. Запускайте його
з PowerShell або Command Prompt у папці `dist\BaseSearch`. Виклик без аргументів
показує повну актуальну довідку.

```text
base-search-cli.exe stats <db>
base-search-cli.exe compact <db> [--vacuum]
base-search-cli.exe peek <table-file>
base-search-cli.exe import <db> <table-file> [...]
base-search-cli.exe search <db> [query...] [--limit N]
base-search-cli.exe analytics <db> [query...]
base-search-cli.exe export <db> <out.csv|out.xlsx> [query...]
base-search-cli.exe browser <db> [--host 127.0.0.1] [--port 7833] [--no-open]
base-search-cli.exe version
```

## macOS і Linux

ZIP репозиторію наразі містить готову збірку для Windows. Користувачі macOS і
Linux можуть скористатися керованою збіркою з джерельного коду:

```bash
git clone https://github.com/IvanK577/BaseSearch.git
cd BaseSearch
./start.sh
```

`start.sh` перевіряє залежності, встановлює зафіксовані frontend-залежності,
збирає браузерні ресурси й програму Rust, а потім запускає Base Search.
`./run.sh` — коротший варіант після встановлення всіх залежностей.

## Збірка з джерельного коду

Перевірене середовище випуску: Rust `1.96.0` і Node.js `22.22.0`. Сумісні новіші
стабільні версії також можуть працювати. Для чистої збірки потрібні Git, npm,
Rust toolchain і системні бібліотеки графічного інтерфейсу.

У Windows потрібні Visual Studio Build Tools із компонентами C++. Щоб створити
той самий портативний пакет, який перевіряє CI, виконайте:

```powershell
pwsh scripts/package-release.ps1
```

Результат з'явиться у
`release_packages\BaseSearch-<version>-windows-<architecture>\`. Ця команда для
розробників не потрібна, якщо використовується готовий `dist\BaseSearch`.

Ручна збірка:

```bash
npm --prefix web-ui ci
npm --prefix web-ui run build
cargo build --locked --release --no-default-features --features release-package --bin BaseSearch --bin base-search-cli
```

Перевірки якості:

```bash
npm --prefix web-ui ci
npm --prefix web-ui run typecheck
npm --prefix web-ui run test:unit
node web-ui/validate-i18n.mjs
npm --prefix web-ui run build
node --test scripts/release-package.test.mjs scripts/bundled-windows.test.mjs
cargo fmt --all -- --check
cargo check --locked --all-targets --no-default-features --features release-package
cargo test --locked --all-targets --no-default-features --features release-package
cargo clippy --locked --all-targets --no-default-features --features release-package -- -D warnings
```

## Обмеження приватності та безпеки

- Base Search не завантажує імпортовані записи, пошукові запити або локальну
  базу до хмарного сервісу Base Search.
- Браузер, розширення, синхронізований профіль, обліковий запис операційної
  системи та експортовані файли мають власні правила безпеки. Для чутливих
  даних використовуйте надійне ПЗ і шифрування диска.
- Користувач із достатнім доступом до комп'ютера або файлів бази може прочитати
  чи скопіювати дані.
- Особистий режим не захищає від іншого процесу, який уже працює від імені того
  самого користувача операційної системи.
- Перевірка цін показує сигнали для людини, а не юридичний, бухгалтерський,
  комплаєнс- або оцінний висновок.

Правила повідомлення про вразливості та підтримувані версії описано у
[SECURITY.md](SECURITY.md).
